# GIS 矢量数据 Agent

一句话操作矢量数据：拖进 Shapefile / GeoJSON，用中文说需求，Agent 规划算子链、真实执行空间运算、生成新图层，并在内置地图上直接看结果。

界面是**纯 Qt 原生控件**（PySide6 + QWidget + QPainter），没有任何 WebView / 浏览器内核，进程里不会出现 `msedgewebview2.exe`。
窗口使用自绘无边框标题栏：顶部空白/品牌区可拖动，右上角「Agent 设置」右侧是最小化 / 最大化 / 关闭；
右下角有尺寸手柄，双击顶部栏可最大化/还原。

## 快速开始

**双击 `启动.bat`** —— 直接打开原生 Windows 窗口，关掉窗口即退出。

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

.venv\Scripts\python.exe native_app.py   # 原生 Qt 界面（等同双击 启动.bat）
```

依赖只需 Python **3.10 ~ 3.13**；`requirements.txt` 里标了实测版本（PySide6 6.12 / GeoPandas 1.2 /
Shapely 2.2 / pandas 3.1 / pyarrow 26），分「核心 / 桌面界面 / 栅格 / 可选补充」几段，
不含任何 Web 服务或浏览器内核依赖。`pyarrow` 用于消费 `pyogrio.open_arrow()` 的
RecordBatch，是 500 万要素按批流式渲染的关键。

启动异常时双击 `调试启动.bat`（带控制台）；启动异常日志在 `data\app.log`。

首次打开点右上角 **示例数据**，会生成成都某片区的 4 个图层（行政区 / 地块 665 / 道路 / 学校），可直接演示。

## 它到底能做什么

对着输入框说人话即可，例如：

| 你说 | Agent 执行的算子链 |
| --- | --- |
| 对地块做 500 米缓冲区，然后按用地类型统计面积 | `buffer` → `area_stats`（第二步自动接上第一步的结果） |
| 用行政区裁剪道路，再统计各类面积 | `clip` → `area_stats` |
| 给学校生成泰森多边形 | `voronoi` |
| 在地块范围生成 1 公里渔网 | `grid` |
| 筛选地块中容积率 > 3 的要素 | `filter` |
| 为学校查找最近的道路 | `nearest` |
| 把学校的属性空间连接到地块 | `sjoin` |
| 检查地块的数据质量 | `describe` |
| 在地图上高亮显示地块 | `highlight` |
| 导出地块为 shapefile | 存成 zip |

**34 个内置算子**（按用途分组，与界面左栏一致）：

| 组 | 算子 |
|---|---|
| 概览 | 数据体检、高亮显示 |
| 栅格 | 栅格体检、栅格裁剪、栅格重投影、栅格重采样、栅格计算、分区统计、栅格镶嵌、栅格转矢量 |
| 几何构造 | 缓冲区、要素转点、凸包、最小外接矩形、泰森多边形、生成渔网 |
| 叠加分析 | 裁剪、求交、叠加合并、擦除 |
| 邻近与连接 | 空间连接、最近邻、范围框选 |
| 属性与统计 | 属性筛选、字段计算、面积/长度统计、形状指标 |
| 整理 | 融合、图层合并、去重、几何简化、投影转换、几何修复、拆分多部件 |

### 自定义工具（按文字描述生成）

工具库里点「＋ 新建工具」，用一段中文描述算法（例如「统计每个地块面内道路的总长度和条数」），
大模型会写一个 `def op(gdf, args)` 函数：先弹预览给你看代码和试跑结果，确认后才入库。

- **契约**：`op(gdf, args) -> (GeoDataFrame 或 None, 说明)`；可用 `pd / np / gpd / shapely`
  以及 `metric(gdf)`（转米制）、`to_wgs(gdf, like)`（转回原坐标系）。参数名写 `other` / `mask` 时，
  引擎会自动把它换成另一个图层的 GeoDataFrame —— 所以「每个面内道路总长」这类跨图层算法也能写。
- **沙箱**：AST 静态检查，禁止 `import`、`while`、文件/网络/系统调用、`__` 属性，
  以及 `read_pickle / read_file / to_file` 等危险方法；运行时只注入白名单内建函数。
  这只是受限执行环境，不是 OS 级隔离——只保存信任的代码。
- **自动重试**：模型很爱写 `import`（提示词里明说了不让写，它还是写）。
  这时不会把错误原样甩给你 —— 程序会把「哪一条违规、怎么改」回灌给模型让它重写，
  最多试 3 次。万一还是不行，错误里会附上生成的代码，并弹出预览框让你自己改完再存。
- **能做的 / 不能做的**：算子只处理**内存里的图层**，不能读写文件、调网络。
  所以「转换矢量文件格式」这类需求做不成 —— 提示词里已经告诉模型遇到这种就直说，
  导文件请用图层右键菜单的「导出」（支持 GeoJSON / GeoPackage / Shapefile zip / CSV）。
- **持久化**：源码存 `data/operators/<name>.json`，下次启动自动装回；工具库按钮、大模型提示词、
  规则引擎三处同步可见，和内置算子完全同权。

每一步以一行式工具调用回显：状态点 + 算子名 + 耗时，细节缩进在下面（要素数变化、告警、统计小表、"新图层"标记、定位 / 属性表 / 导出）。

## 界面说明

视觉参照 **Claude Code 桌面端**：近乎单色（暖白纸底 #faf9f5 + 近黑文字），全界面只有一个强调色（陶土橙 #d97757），
靠 1px 暖灰细线分隔、不用大圆角卡片和阴影；助手回复是纯文本段落（不套气泡），用户消息是一块浅色底块。

- **左栏**：暖灰底，拖入即载入；图层列表带显隐勾选，**双击图层名可直接改名**，
  右键菜单：缩放到图层 / 属性表 / 图层样式 / 重命名 / 复制图层 / 只显示此层 / 显示全部 / 导出（4 种格式）/ 删除；
  重命名会自动避开重名（加序号），也能 `Ctrl+Z` 撤回。点击拖拽区打开**自定义导入弹窗**：
  可以添加文件或 `.gdb` 文件夹，GPKG / FileGDB 会列出内部图层，勾选后再导入。
  左栏上方是「图层 / 工作区」两个页签：工作区按「gis-agent → 未分组 → 会话」
  展示历史会话，每个会话带最近更新时间和图层引用；点开会话会同步恢复对话和图层。
  图层数据只存共享 `data/cache`，不按会话复制，会话状态只记录引用。
  下方工具库**先分「矢量」「栅格」两大类**，
  再按功能分组（矢量：概览 / 几何构造 / 叠加分析 / 邻近与连接 / 属性与统计 / 整理 / 我的工具；
  栅格：概览 / 处理 / 分析 / 转换）。**一级分类和每个功能分组都可点击收缩**，
  分组标题带数量、组间以发丝线分隔、组内两列并排；点一下就把该算子的指令模板写进输入框，悬停看算子说明。
  输入框等标准控件的右键菜单、Qt 原生对话框会自动加载 `qtbase_zh_CN` 翻译，显示中文而不是
  Undo / Cut / Copy 这类英文。
- **在线地图**：工具库顶部「底图 → 在线地图」打开弹窗，填写「在线地图地址 / 加载方式 /
  在线地图名称」后确认加载。支持 **XYZ 瓦片**（`{z}/{x}/{y}`、TMS 的 `{-y}`、子域 `{s}`）、
  **WMTS 瓦片模板**（REST 的 `{TileMatrix}/{TileCol}/{TileRow}`，以及天地图这类 KVP 写法
  `TILEMATRIX={z}&TILEROW={y}&TILECOL={x}`）和 **WMS**（保留地址里的 LAYERS/STYLES，
  按当前视图自动补 BBOX/WIDTH/HEIGHT/SRS（1.3.0 用 CRS））。弹窗还支持可选 **Token**
  （参数名可选 `token` / `access_token` / `key` / `tk` / `apikey` 或自定义）、**自定义参数**
  （每行 `key=value`）和**自定义请求头**（每行 `Name: value`）；Token 也可在地址、参数或请求头里
  用 `{token}` 引用（例如 `Authorization: Bearer {token}`，此时不再重复追加查询参数）。
  **天地图**：加载方式选 **WMTS**，Token 参数名填 `tk`（贴入天地图地址会自动带出），矢量底图地址模板：
  ```text
  https://t{s}.tianditu.gov.cn/vec_w/wmts?SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0&LAYER=vec&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles&TILEMATRIX={z}&TILEROW={y}&TILECOL={x}&tk={token}
  ```
  把 `vec_w/vec` 换成 `img_w/img`、`ter_w/ter` 可切影像/地形；程序会按天地图规则把
  最小层级夹到 1，并让 `{s}` 使用 `t0`…`t7`。注意不要填
  `https://t0.tianditu.gov.cn/img_c/wmts/{z}/{x}/{y}` 这种 REST 路径式地址，天地图会返回
  404；也不要用 `_c`/`TILEMATRIXSET=c`（当前渲染是 Web Mercator，用 `_w`/`w`）。
  瓦片是**逐张上屏**的：每拿到一张就合成一次当前视口，最后一张到齐后再用完整图替换，
  不会等所有瓦片都下载完才显示；在线瓦片还跑在单独线程，不会把本地栅格的渲染堵在后面。
  在线底图登记成栅格图层放在图层栈底部，
  可像普通底图一样显隐、缩放定位、调不透明度、删除，并随会话保存地址、加载方式、Token 和自定义参数
  （恢复时会重新取图，不缓存图片）。
- **图层样式**：图层右键「图层样式…」打开弹窗，左边实时预览、右边按几何类型只显示相关项：
  面图层的填充色 / 填充不透明度 / 描边色 / 描边不透明度 / 线宽，线图层的描边与线宽，
  点图层的点颜色 / 点大小；栅格图层可改不透明度、拉伸方式（累计裁剪 / 最小–最大 / 不拉伸）和 gamma。
  **要素标注**选一个属性字段、字号、文字颜色和白色描边开关，标注按当前视野取点并自动避让，
  **线要素沿线方向旋转排字**（锚点取线中点，和 QGIS「沿线上放置」一致），同名道路挨得太近不会
  重复堆叠（参考 QGIS 的「合并相连线」），超过 40 字截断；取数与缓存跑在独立线程，
  旧视野的取数会被新视野打断，拖动时标注立刻跟上。没有空间索引的源文件
  （GeoParquet、无 `.qix` 的 Shapefile）还会在图层进来时后台读一次**整层锚点表**，
  之后平移/缩放只做内存筛选——614MB 的村界面数据从「每拖一次重读 4 秒」变成一次 4 秒、
  之后 0.1ms。
  保存后地图立刻按新样式重画，颜色同步到图层行色块和图例；样式随会话保存，切换/重开会话还在。
  **没动过样式的图层外观和以前完全一致**。
- **中间**：QPainter 自绘地图，支持拖拽平移、滚轮缩放（以光标为中心）、双击放大、点击看属性、经纬网与比例尺。
  鼠标移动不在地图上做悬停命中测试，避免大图层因悬停触发整层读取。  **Shift + 拖拽 = 框选**（只作用于左栏当前图层）：选中的要素描朱红边 + 淡填充，状态栏实时报数量，
  这时在右栏说一句「做 500 米缓冲区」，会**先把选中要素单独成一层**再执行——算子从此能作用于"一部分"而不是整层。
  Esc 先清选区、再清高亮；点空白处也取消选择。
  **源文件图层的宽视野缓存**：Shapefile / GPKG 没有空间索引，一缩到省域就是整文件重读（47 万条道路实测
  整帧 6s，拖动/缩放时反复重来就是「卡 5~8 秒」）。大图层打开后会在后台按固定粗容差把整层读**一次**、
  建成一套约 30 MB 的路径缓存（`_LodWorker` + `vectorstream.build_lod_paths`），之后
  **每像素地面米数 ≥ 45（约 1:17 万及更远）** 的平移/缩放只在内存里筛批，整省帧从 ~6s 降到 ~0.3s；
  城市级仍按 bbox 读窗口保证细节（缓存太粗时自动退回）。点图层、超大面图层（顶点超 400 万）不建缓存。
  **键盘**：`←→↑↓` 平移（按住 Shift 步长 ×4）、`+`/`-` 缩放、`Home` 全图；**中键拖拽**也能平移（GIS 老习惯）。
- **地图对比**：点地图右上角 `◫`，选左右两张栅格底图，支持左右 50/50 分屏、上下分屏、
  卷帘拖动、透明度叠加、闪烁对比；中间分隔条可拖动改比例（卷帘模式下分隔条实时跟手，
  左右两个方向拖动都即时露出对应一侧的地图），两侧视图（平移/缩放）实时同步，
  再点一次按钮退出对比。
  **右键菜单**：全图 / 缩放到当前图层 / 把选中要素存成图层 / 清除选区 / 导出当前视图 / 导出当前图层。
- **属性表 ↔ 地图联动**：点表格任意一行，地图立刻高亮该要素并缩放到它；表头点击排序（再点反向），
  顶部筛选框对任意列做包含匹配，超过 200 行进分页——不再截断成"只能看前 500 行"。
- **右栏**：白底对话区；顶部是「对话 / 轨迹」两个页签，后台任务胶囊、面板开关和清空按钮；
  底部输入容器带模型选择器（打开模型设置）和实时统计（轮数 / 工具步数 / tok/s /
  总 token / 缓存命中 / 上下文占比）；执行时上方出现「正在调用工具 · xxx」状态条。
  Enter 发送 / Shift+Enter 换行，
  **`↑`/`↓` 翻之前发过的指令**（单行时接管，多行不会抢光标），Ctrl+O 打开文件，Ctrl+0 全图。
  Agent 拿到计划后会先显示一张「工具调用计划」卡：逐行列出算子、目标图层和关键参数，
  执行中实时更新「执行中 / 完成 / 耗时 / 失败」，不再是只转一个计时圈。
- **逐步确认**：每一步执行前都会弹窗确认，可点「执行这一步 / 跳过这一步 / 取消任务」；
  下方还能输入补充要求（例如「缓冲区改成 800 米」「只处理当前选区」），模型会先重写
  这一步再执行；改不出来会停下提示，不会按旧参数硬跑。
- **Agent 设置**：头部最右侧的「⚙ Agent 设置」管理技能和逐步确认开关。技能就是
  根目录 `skills/` 下的 Markdown 卡片，在设置里可以添加、编辑、启用/禁用、删除；
  启用的技能会自动拼进下一次规划提示词（只对模型规划生效）。
- **工具库管理**：「Agent 设置 → 工具」按矢量/栅格分组列出工具库里的全部算子，支持按
  名称/说明/算子名搜索。取消勾选即停用：左栏工具库不再显示、不再交给大模型，执行前也会
  被拦下并提示去哪儿启用；自定义工具还能编辑代码/改名/换分组/删除，内置工具只能停用
  不能删。停用列表存在 `data/settings.json` 的 `tools_disabled` 里，重启后仍生效。
- **导出视图**：`Ctrl+Shift+S`（或地图右键）把当前画面存成 PNG —— 连图例和缩放键一起抓，出报告直接用。
- **可撤销**：`Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`）。因为算子只产出新图层，撤销 = 把派生层摘掉/放回，
  包括「删掉的图层按原位置还原」，栈深 20 步。
- **载入有进度**：状态栏右侧一根细进度条 + 「取消」，按「文件 i/n」推进；取消后**当前文件读完就停**，
  已经载完的图层保留。

**图标**：陶土橙圆角底 + 一个面要素轮廓（带三个顶点句柄），第二层淡轮廓暗示图层叠置。
同一套绘制代码三种用法——运行时 `make_icon()` 现画多尺寸 QIcon（16/24/32/48/64/128/256）、
`native/assets/icon.png`（256）、`native/assets/icon.ico`（多尺寸，做桌面快捷方式用）。
小尺寸会自动减笔画：16/20 px 只留实心面，24~40 留轮廓 + 句柄，更大才画后层。
重新生成：`python tools/make_icon_assets.py`。

## 规划引擎：两级

1. **规则引擎（默认，离线可用）**
   内置中文指令解析器：图层名模糊匹配、单位与数字抽取、多条指令按"然后 / 再 / ；"拆句，并把上一步的输出自动串给下一步（流水线）。
2. **大模型规划（可选，但推荐）**
   「模型设置」里填任意大模型接口，Agent 会把图层清单、字段、算子参数 schema 一起发给模型，拿回结构化 JSON 计划再执行。接口超时或返回不合法时**自动回退**规则引擎（连续失败会静默 60 秒，避免每条指令都卡住）。执行失败会把错误和当前 schema 回灌给模型，最多自动修复 2 次。
   Key 只存在本机 `data/settings.json`（原子写 + 尽量收紧权限）。

**接了大模型之后，自然语言才是真正自由的。** 规则引擎只认模板句式（「对 X 做 500 米缓冲区」），
而大模型能把「帮我看看每个小区周边 300 米内有没有地铁站」翻译成算子参数。

普通对话（问「你是什么模型」「1+6666 等于多少」、闲聊、问常识）走**独立的 chat 模式**，
不要求模型输出 JSON，也不需要先载入数据；只有明确的 GIS 意图才进算子规划。

### 用 @ 指定图层

输入框里敲 `@` 会弹出图层补全列表（像 opencode 里 `@` 引用文件那样），
选完图层名就带上了，可以接着打后半句：

```
对 @小区 做 300 米缓冲区，然后和 @地铁站 求交集
```

弹窗和应用主体同一套配色（暖白底 + 橙色强调 + 细边框），每行长这样：

```
┌────────────────────────────────┐
│ 选择图层                5 个   │
│ ●  小区               Polygon   │
│ ●  小区_合并          Polygon   │
│ ●  地铁站          Point · 8,612 │
├────────────────────────────────┤
│ ↑↓ 选择 · Enter 确认 · Esc 取消 │
└────────────────────────────────┘
```

- 左侧小圆点按**几何类型**着色（点=蓝、线=金、面=绿），扫一眼就知道选的是什么。
- 右侧是几何类型和要素数，逗号分隔。
- 选中行浅底 + 左侧橙色强调条，和应用里图层列表的选中态一致。
- 高度跟着候选数走 —— 只有 1 个候选时不占一整屏。

`@` 的意思是**点名道姓**，比「当前选中图层」优先：

- **精确优先**：`@小区` 就是「小区」，不会因为还有个「小区_合并」就选错。
- **显式覆盖**：哪怕当前选中的是别的图层，也按 `@` 指的来。
- **有歧义就问**：`@小` 同时匹配「小区」和「小区_合并」→ 直接弹澄清让你点，不猜。
- **名字写错会报错**：`@不存在` 会说「没有叫「不存在」的图层」，不会悄悄操作到别的图层上去。
- 带空格的图层名（`@2024 年 GDP`）和带文件名的（`@gis_osm_roads.shp`）都认。
- 邮件地址（`a.b@x.cn`）不会被误当成提及。

内部处理分两步（`app/mentions.py`）：
1. **语法解析** —— 认出哪些是提及；粗抓到标点为止，
   这样「@小区 做缓冲区」和「@2024 年 GDP」都能先抓下来。
2. **结合图层名截断** —— 从长到短试真实图层名，确定该取哪几个词。
   这一步需要图层库，所以和解析是分开的（解析可以脱离图层库单测）。

`@` 标记本身不会发给模型（模型看到 `@` 会当成特殊 token），
名字会留在正文里给规则引擎认；大模型模式下还会额外告诉它
「用户用 @ 明确指定了图层：X」，免得它自作主张换成名字相近的图层。

### 支持的 API 格式

设置窗口里可以切换接口格式 —— 不同厂商的 URL、鉴权头、请求体、响应结构都不一样，
`app/api_formats.py` 把这些差异收敛成适配器：

| 格式 | 端点 | 鉴权 | 响应取值 |
|---|---|---|---|
| OpenAI Chat Completions（默认，兼容面最广） | `{base}/chat/completions` | `Authorization: Bearer` | `choices[0].message.content` |
| OpenAI Responses | `{base}/responses` | `Authorization: Bearer` | `output[].content[].text` |
| Anthropic Messages（Claude） | `{base}/messages` | `x-api-key` + `anthropic-version` | `content[].text` |
| Google Gemini | `{base}/models/{model}:generateContent` | `x-goog-api-key` | `candidates[].content.parts[].text` |
| Ollama 原生 | `{base}/api/chat` | 可无鉴权 | `message.content` |

- 预设按钮会**同时**改好地址、模型和格式（DeepSeek / 通义千问 / OpenAI / Ollama / Claude / Gemini）。
- 底下有**实时预览**：显示「当前设置会发成什么样」的 POST 地址和请求头，填错当场就能看出来。
- **测试连接**按钮发一个最小请求，验证地址/密钥/模型/格式对不对，不用来回试。
  - 在**后台线程**里跑，界面不会冻住；测试中可随时点「取消」。
  - 失败时给的是**人话**而不是原始异常：401 说鉴权失败、403 点明是哪个模型没权限、
    404 说地址/端点路径不对、429 说限流或额度、5xx 说这是对方服务的问题；
    连不上会区分「域名解析不了」「连接被拒绝」「HTTPS 握手失败」「超时」。
  - 地址、Key、模型没填全时**不发请求**，直接告诉你缺哪一项。
  - 服务端原话会附在后面（「服务端说：…」），便于直接找服务商。
- **高级**里能改端点路径（支持 `{model}` 占位）和附加请求头，用来对接自建网关或私有代理。

### 大模型驱动的完整闭环

```
用户自然语言
   │
   ├─► 大模型理解 ──► 输出 {plan, reply, clarify, new_operator}
   │        │
   │        ├─ 有 plan ──► 预检（schema + 图层/字段存在性）──► 执行
   │        │                    └─ 失败 ──► 错误+schema 回灌 ──► 修正计划（最多 2 次）
   │        │
   │        ├─ clarify ──► 界面渲染成**可点选项** ──► 用户点一个
   │        │                    └─「原始需求 + 问题 + 回答」一起回灌 ──► 重新规划 ──► 执行
   │        │
   │        ├─ new_operator ──► 真的写一个工具 ──► **先给用户看代码** ──► 确认后入库
   │        │                    └─ 用户可以改代码再保存；入库后自动重跑原任务
   │        │
   │        └─ 做不到 ──► 说清缺什么 + 给 1~2 个用现有算子能做的替代方案
   │
   └─► 大模型不可用 ──► 规则引擎兜底（并**如实告知**用户这次走的是规则引擎）
```

几个刻意的设计：

- **有歧义就问，不猜。** 模型判断图层/字段不明确时输出 `clarify`，界面把它渲染成一排**可点按钮**，
  用户点一下就等于回答了——答案会连同「最初的需求」一起回灌给模型重新规划，
  而不是让用户再打一遍「道路」。
- **「做不到」要说人话。** 模型认为现有算子做不了时，要讲清缺什么、为什么不行，并给出替代方案；
  如果缺的是**算子能力本身**（组合现有算子怎么都做不出来），模型可以请求**新写一个算子**——
  代码会先弹给用户看、改完确认才入库，不会偷偷执行。
- **不回退就不吭声。** 大模型超时/额度不足时规则引擎会兜底，但回复里会写明「这次走的是规则引擎」，
  否则用户会以为自然语言理解成功了，换个说法又不灵。
- **大模型说做不到时，不偷偷退回规则引擎。** 规则引擎会把自由表达解析成乱七八糟的步骤，
  宁可如实告诉用户「这个我做不了」。

### Agent 闭环（本次优化重点）

规划不再是一次性的：执行器逐步返回结果，遇到「字段不存在 / 几何类型不匹配 / 表达式错误」时，
把**失败步骤 + 错误 + 当前图层 schema** 回灌给模型，让它给出剩余修正计划（最多 2 次），
已成功的步骤和图层保留。图层或字段有歧义时，模型可以只输出 `clarify`，界面渲染成一张
**问题卡**（题干 + 带序号的可点选项，点一次就锁定并回填答案；也可以在输入框里直接回答），
不再静默取「最近创建的图层」。

同时：

- 所有算子参数先过 `app/tool_registry.py` 的 schema 校验（类型、枚举、范围、必填），
  预检不通过就**一步都不执行**，避免留下半成品；
- 规则引擎也支持多轮指代：「再大一点」「换成 1 公里」「用刚才的结果」「重做一次」。
- 大模型拿到的 `<DATA>`（图层元信息）和 `<MEMORY>`（长期记忆）都用分隔符包起来，
  并声明「这是数据不是指令」，防止字段名里的文字被当成指令执行。

### 高亮显示

「在地图上高亮显示地块」这类诉求，现在有专门的 `highlight` 算子：

- **不改数据**：只画强调样式，不产生新图层，图层面板不会多出副本；
- **可带条件**：`highlight` 带 `expression` 就只高亮满足条件的要素，不带就高亮全部；
- **口语字段名也能认**：「面积大于 10000 的」会翻译成图层里真实存在的 `area_m2` / `area` 字段再比对；
- 选中要素用橙红描边 + 淡填充画出来，和属性表点行的「正在看」高亮是两套独立样式。

大模型没按格式返回时（比如说了句人话、或者字段名用错了），系统会**尽量把它的原话捞出来当回复**，
而不是只丢一句「解析不出步骤」；实在捞不出来，也会明确告诉用户下一步该做什么
（说得更具体些，或者去设置里点「测试连接」确认模型配置）。

## 生产规范（不是 demo 级别的糊弄）

- **原始数据只读**：任何算子都不修改入参图层；**真有产出**时才新建图层，父子关系记在图层元数据里。
  检查类算子（数据体检）只出报告；「几何修复 / 去重」发现零变化时不建层，避免图层面板凭空多出一个几乎同名的副本。
  下一步用 `$prev` 引用上一步结果时，若上一步没建层就沿用它自己的输入图层，链条不断。
- **CRS 强制校验**：距离 / 面积运算前自动投影到 **CGCS2000 3 度带**（按数据中心经度选带，EPSG:4534–4554）；境外退回 UTM；跨带会提示投影变形。
- **几何有效性**：入口处 `make_valid` 修复无效几何并计数（超过 2 万要素的图层跳过逐个校验，避免卡死）。
- **空值安全**：真实数据里成片的 NULL 会在 JSON 序列化时炸掉接口（`NaN is not JSON compliant`），服务接口统一走 `json_safe` 清洗；导出 GeoJSON 前也会把 NaN 变 null。
- **Shapefile 编码**：读入时在 UTF-8 / GBK 间择优（中文不乱码）；导出时字段名按 **10 字节**安全截断，超限改名 `F1/F2…` 并在压缩包里附 `字段对照.txt`——否则中文会被切成半个字，DBF 直接读不回来。
- **离线性**：默认地图是自绘渲染器，不依赖在线瓦片、不依赖 CDN；需要底图时可在工具库
  「底图 → 在线地图」手动添加 XYZ/WMTS/WMS（天地图用 WMTS），只有该图层可见时才联网。
- **选区即输入**：框选的要素会被复制成一个独立图层（`原层名_选中N`）再参与运算，不污染原图层；
  这一层同样可以撤销 / 导出 / 删掉。

## 渲染管线（对照 QGIS 源码实现）

地图完全用 QPainter 自绘（Web Mercator）。渲染管线逐项对照 QGIS 的源码结构实现，
用到的参照类：

| 本项目 | QGIS 对应 | 说明 |
| --- | --- | --- |
| `_RenderJob` | `QgsMapRendererJob` | 一次渲染任务的上下文 + 世代号（epoch） |
| `_RenderWorker` | `QgsMapRendererParallelJob` | 常驻调度线程，请求队列只留最新一个；多图层时线程池并行画层 |
| `_LayerJob` | `LayerRenderJob` | **每个图层渲染到自己的一张 QImage**，按原图层顺序回传 |
| `_compose_async()` / `_ComposeWorker` | `composeImage()` | 常驻合成线程把各层 QImage 叠成整帧，UI 线程只接一次结果 |
| `_compose()` | `composeImage()` | 同步合成（单测/兼容路径） |
| `_img_cache` | `QgsMapRendererCache` | 图层级缓存：键 = 视口 + 尺寸 + dpr + 图层几何版本 |
| `_RenderSet` | 渲染范围 + `QgsSimplifyMethod` 的组合 | 一个「范围 + 容差」下的一整套路径 |
| `_select_indices()` | `QgsFeatureRequest::setFilterRect(extent)` | 视口矩形筛要素，**筛完全量画** |
| `vectorstream.paint_stream_layer()` | `QgsVectorLayerRenderer::render()` | 大图层按屏幕范围取要素、分块建路径、立即画，不缓存整层路径 |
| `app/vector_provider.py` | `QgsVectorDataProvider::getFeatures(setFilterRect)` | 源文件图层只读文件头；`open_arrow` 按屏幕 bbox 逐批产出 |
| `pyarrow.RecordBatchReader` | `QgsFeatureIterator` | 一批 WKB 解成 shapely，画完即丢，不物化整个窗口 |
| `_simplify_tol()` | `QgsSimplifyMethod::tolerance` | 容差以**屏幕像素**为准（0.8 px 对应地面距离） |
| `_split_subpixel()` | `QgsSimplifyMethod::threshold` | 屏幕尺寸 < 1.5 px 的面要素降为点绘制 |
| `_keep_mask()` | 简化器的退化保护 | 小要素被简化没了就回退原几何 |

关键机制：

- **要素选取不抽样（重要）**：范围里相交的要素**一个不少**全部进渲染集。
  任何抽样/配额/预算压制都会在屏幕上变成一块一块的空洞 —— 因为渲染集一旦被
  当成「这个范围已经画好了」缓存下来，缺的要素就再也不会被补上。
  渲染集的完备性是复用判据（`rect` 覆盖当前视口）成立的前提。
- **不做覆盖范围记账**：每套渲染集只记录自己那个矩形。判据是
  「**某一个**集合完整包含视口」，不是「若干集合的并集包含视口」——
  后者在平移出几段不相邻区域后会把中间的空白也当成已覆盖，正是矩形空洞的来源。
- **合成绝不叠旧帧**：每次合成都在干净画布上从零叠所有图层图，final 帧完成后
  才登记为可复用；provisional 帧同样从零合成，只用于显示、不登记 `_frame_sig`。
  在上一帧上继续叠图层会让 14% 的填充叠成实色，看起来就像「有些地方渲染错了」。
- **合成在独立线程**：图层 QImage 在 `_ComposeWorker` 里叠成整帧，主线程只做
  `QPixmap.fromImage` + `update`；拖拽大栅格时不会再被逐层 `drawImage` 卡住。
  栅格回调在矢量帧未完成时只更新图，不重复触发全屏合成。
- **平移只在「露出的空白够宽」时重绘，但松手一定重绘**：拖拽期间画面是把整帧
  当位图偏移贴上去的（`paintEvent`），偏移多少就露多少空白。重绘阈值取
  `min(视口 × 0.3, 72 px)` —— 只用比例的话，900 px 宽的视口要拖 270 px 才重绘，
  小幅拖拽永远等不到，右/下会留一圈空边。松手时（`_end_pan`）无条件重绘一次，
  因为这时候手停了、正是补齐的时机；`tx/ty` 没变则不重绘，避免纯点击白白渲染。
- **过期图层图按自己的视口重投影**：视图一变，缓存里的图层图就过期，但新图还在渲染。
  这时按 `(0,0)` 贴会把整幅图拉回拖拽前的位置（就是「松手后闪一下才归位」）。
  每张图都记着渲它的那个视口（`_layer_views`），合成时套
  `translate(tx,ty)·scale(s/s0)·translate(-tx0,-ty0)` —— 对世界坐标精确，
  纯平移是整数位移，缩放是精确等比变换。
- **视口移出数据范围也要出空帧**：`_make_snapshot()` 为空时不能一律「继续显示旧帧」，
  那只对「几何还在建」成立。判断依据是 `_build_pending()`：没有在飞的构建、
  也没有可用渲染集，就说明这个视口里确实没东西（拖到数据范围外了），
  必须合成空帧，否则屏幕上的旧内容永远不动，看着像「拖不动」。
- **世代号（epoch）**：视图一变就 +1，旧世代的帧和图层图一律丢弃，旧帧不会覆盖新帧。
- **取消不阻塞**：对应 QGIS 的 `feedback()->cancel()`，旧任务在图层间隙、流式
  batch/chunk 边界收工。新视图到来时**连正在跑的任务也标记取消**：大矢量一帧
  可能要几秒，不取消就会让最新视图排队等它画完；已经画出的部分保留，旧帧在屏上
  按新视口平移，不会清空。连续滚轮时防抖只提交最后一个视图，不会每帧都半途而废。
- **按图层渲染 + 合成**：每层只遍历一遍自己的要素包围盒，一层画完就能先合成。
- **大图层流式渲染**：超过 25 万要素的图层不再预建整层 `QPainterPath`，
  而是按当前屏幕矩形筛出要素，分 4096 个一块取几何、简化、建路径、立即画，
  路径用完即丢。参照 `QgsVectorLayerRenderer` 的 extent 过滤 + 逐要素渲染，
  避免“整层几何 + 整层路径”双份内存；小图层仍用渲染集缓存换平移/缩放速度。
  可用 `GIS_AGENT_STREAM_VECTOR=1` 强制所有图层走流式，`=0` 全部走缓存。
- **流式中间帧**：每画完一块，把当前图层图复制一份发给主线程合成
  **provisional 帧**（小窗口约 0.06 s、大窗口 0.12 s 一次，`layerProgress` 信号），所以要素会一块块
  出现在屏幕上，而不是整层画完才换图。中间帧只显示、不进图层缓存、不登记
  `_frame_sig`；整帧完成后才由 final 帧替换。
  不是“逐要素上屏”：Qt 每次 `drawPath` 的固定开销远大于顶点开销，
  逐要素画 47 万条道路会慢一个数量级，块级渐进才是可用的流式粒度。
- **源文件 / 磁盘缓存 provider 模式**：Shapefile / GeoPackage / GeoJSON / KML / GML
  （以及 `.gpkg` / `.parquet` 磁盘缓存）导入时**不论要素数**都只读文件头
  （要素数、范围、CRS、字段），不再先整份 `gpd.read_file()`；
  GeoParquet 走 `pyarrow.ParquetFile.iter_batches()`；
  其它格式走 `pyogrio.open_arrow(..., bbox=...)`：OGR 按 RecordBatch 流式产出，
  `pyarrow` 消费一批、解成 shapely、画完即丢，不再把整个 bbox 物化成 GeoDataFrame。
  首个批次通常几十毫秒就能到渲染线程，500 万要素也不会先申请一个整层数组。
  算子/导出/拾取等需要全量数据时才懒加载 `Layer.gdf`。
- **投影大图层的渲染 LOD 缓存**：GeoParquet 若源 CRS 是投影坐标，先按等效 WGS84
  容差在**源 CRS 里简化、再投影**（直接投影 4480 万顶点要数秒，简化后通常只剩
  十几万到几十万顶点）；简化结果按 2 的幂次容差档位缓存整层 WGS84 几何，
  平移只做 bbox 过滤，缩放一档可复用 2.5 倍容差内的相邻档位。实测 21k 块 /
  4480 万顶点的图层：首帧约 4 s，同一档位平移/一级缩放约 0.2~0.4 s，
  跨 4 倍档位才重建一次（约 4~5 s）。缓存上限 96 MB，只存简化后的几何，
  不保留原始全量；`read_bbox()` 仍返回完整几何，不受渲染简化影响。
- **流式渲染不等于 0 内存峰值**：PyArrow 的 `ParquetFile` 在销毁前会保留读过的
  column chunk。现在按 row group 重开/销毁 reader，并在扫描结束调用
  `pyarrow.default_memory_pool().release_unused()` 把页还给 OS。同一 21k 块 /
  4480 万顶点图层稳定后 WorkingSet 约 180–190 MB（含 Qt + 依赖约 146 MB 基线），
  不是 0.9 GB。旧式单 row-group 缓存第一次全文件扫描瞬时峰值约 0.9 GB，扫完
  即降；新建缓存用 `row_group_size=512`，同样扫描峰值约 280 MB。当前 586 MB
  的村行政区划缓存已重建为 42 个 512 行 row group，会话启动峰值实测从约 1.0 GB
  降到约 460 MB，空闲稳定在约 253 MB。
- **栅格图层本身不是 1 GB 的来源**：48128×30342、带 overview 的影像在
  1816×986 窗口下，源 block cache 只有几 MB，视口 QImage 约 1.8 MB；整份
  8 图层会话只显示这张栅格时 WorkingSet 约 230 MB，从全隐藏状态勾选它只增加
  约 8 MB。`TILE_CACHE` / `SOURCE_CACHE` 各封顶 64 MB，GDAL 块缓存 128 MB。
  如果启动时看到 1 GB，通常是“村行政区划”的旧单 row-group 缓存还在流式渲染：
  PyArrow 暂时保留约 645 MB column chunk，4~5 秒后释放；栅格加入本身不是这条峰值。
  该缓存已重建为 42 个 512 行 row group，现在启动峰值约 460 MB。
- **属性表只读属性列，不加载几何**：provider 图层打开属性表走
  `Layer.attrs_frame()` / `VectorProvider.attrs_frame()`：GeoParquet 只读非几何列，
  Shapefile/GPKG/GeoJSON 用 `pyogrio.read_dataframe(read_geometry=False)`。
  21k 块 / 4480 万顶点的图层，旧路径为显示属性表调用 `layer.gdf`，会把整层 WKB
  解码并缓存；新路径 0.45s、WorkingSet 约 179 MB（属性表数据约 4.65 MB），
  `Layer.gdf` 保持 None。点表格一行时只解码该要素用于高亮/定位。
- **悬停功能已移除，点击拾取也不触发全量加载**：鼠标移动不再做命中测试；
  点击时 provider 图层（`c.geoms is None`）的 `_hit_test()` 走
  `VectorProvider.hit_test()`：GeoParquet 用 LOD 缓存里的简化几何找最近要素，
  再按源文件行号只读**属性列**（`attrs_at()`，不读几何）；Shapefile/GPKG 只读
  点击点附近的小 bbox。实测 21k 块 / 4480 万顶点的图层，点击从 15.5s、
  内存 4.3GB 降到 0.02s、只增加约 6MB 属性表内存，`Layer.gdf` 保持 None。
  `_select_rect` / `zoom_to_feature` 在 `_gdf` 未加载时也不会再为 provider 图层
  建全量几何索引；整层框选仍不支持，属性表按行定位改为单要素读取。
  注意：Shapefile 没有空间索引时，bbox 过滤仍会顺序扫描 `.shp`，只是不把范围外
  要素读进内存；GPKG 有空间索引时窗口读取明显更快。
- **恢复会话也不全量读缓存**：溢出缓存（`.gpkg` / `.parquet`）同样能作为 provider。
  GeoParquet 用 `pyarrow.ParquetFile.iter_batches()` 逐批解 WKB，打开时只读文件头；
  恢复图层先填会话里保存的 count，不再为了图层面板显示一行元信息而
  `gpd.read_parquet()`。实测一个 21k 块、4480 万顶点的缓存图层，旧路径
  `gpd.read_parquet()` 峰值 3 GB 以上，新路径空闲恢复约 220 MB（隐藏状态）。
  Parquet 的 bbox 没有空间索引时仍需扫 batch，但每次只驻留一个 batch。
- **Shapefile 自动 `.qix`**：打开 `.shp` 时后台用 GDAL `ogrinfo` 补一次空间索引
  （只写同目录 `.qix` 旁车文件，不碰 `.shp/.dbf`；`GIS_AGENT_AUTO_INDEX=0` 可关）。
  470k 道路实测：城市窗口从 2.8 s 降到 0.27 s；500 万 Shapefile 首次打开会先顺序
  流式显示，索引建好后平移/缩放才走索引。也可用
  `tools/build_spatial_index.py layer.shp` 提前建好。
- **500 万点降为像素桶**：点图层在当前视口超过 8 万个点时，把世界坐标量化到
  1 个设备像素，同一个像素只画一次 `drawPoints`。这不是抽样：被占用的像素一个不少；
  5M 点 / 1000×700 实测从 96 s 降到约 6 s，首帧 0.2 s；放大到城市窗口后
  `point_dots=False`，恢复 3.4 px 圆点。需要逐点圆点对比时设
  `GIS_AGENT_POINT_DOTS=0`。
- **多图层并行 job**：每个图层一个任务、各自画到独立 QImage，线程池并行；
  但仍按原始图层顺序回传 `layerReady`，上层先画完只暂存，不会先盖住下层。
  实测 3 个图层 4.20s → 2.75s，整机冒烟 12s → 8.1s，最终帧逐像素一致。
  `GIS_AGENT_PARALLEL_LAYERS=0` 可退回串行对照。
- **图层缓存**：同视口下切显隐、调图层顺序直接复用上次的图层图。
  缓存键用**图层自己的**几何版本号，别的图层重建不会把这张图废掉。
- **屏幕像素级容差**：0.8 像素对应的地面距离，放大后自动变细；
  小要素靠逐要素退化检测（空 / 面积缩水 >60%）回退原形。
- **亚像素要素画成点**：省域视图下 24 万栋建筑总共只剩 4 个顶点，
  按容差简化等于让它们凭空消失。改成画 1 个设备像素的点：
  既不丢要素，也省掉海量无用顶点（用 `drawPoints` 的 hairline 笔——
  笔宽 > 1 时 Qt 会按端帽把退化的点画成横条，8 万个点能糊成一整片实色）。
- **路径按批合并**：Qt 每次 `drawPath` 的固定开销远大于顶点开销，
  逐要素画 47 万条道路要 800 ms，按 256 个要素一批合并后只要 190 ms。
- **线宽按比例尺分档（这条最省钱）**：`1.6px` 圆头笔会走 Qt 的**完整抗锯齿描边器**
  （每个顶点生成四边形 + 端帽 + 拐角连接），而**整数宽度 1** 有一条快速路径。
  实测 47 万条道路 / 94 万顶点，省域视图 1.6px 要 1914 ms，1.0px 只要 79 ms（24 倍），
  落笔像素数几乎一样（11.9 万 vs 11.0 万）。所以「每像素地面米数 ≥ 45（约 1:17 万）」
  一律画 1px —— 这个比例尺上 6 米宽的路本来就不足 0.01 像素，1px 才是正确画法。
- **每个环/部件的包围盒用 numpy 一次算完**：原来是逐个 part 对切片做 4 次 min/max，
  47 万个 part 就是近 200 万次 Python 切片归约；改成 `np.minimum.reduceat` 按 part 起点归约。
- **分片几何构建**：每片 10 ms 预算，构建期间界面照常响应；载入数据期间
  自动暂停构建，避免和解析线程抢 GIL（实测 4 个大图层抢着跑要 50 s，串行 23 s）。

**效果（4 个图层 83.5 万要素，地图视口 715×805）**

| 场景 | 优化前 | 现在 |
| --- | --- | --- |
| 省域视图重绘（渲染集已就绪，纯绘制） | 3.64 s | **0.35 s** |
| 缩到 1:1M（重建渲染集） | 1.62 s | **1.00 s** |
| 缩到 30 m/px（重建渲染集） | 0.31 s | 0.31 s |
| 平移 120 px（渲染集复用） | 0.09 s | 0.10 s |
| 缩回省域 | 1.93 s | **0.27 s** |
| 载入 + 首次出图 | 23.0 s | 20.0 s |
| 同视口清空重建 vs 缓存画面 | 像素差异 **0.005%~0.03%** | 0.0245%（251 / 1,024,000 px） |

放大那两级剩下的时间主要在**几何构建**（把 47 万条道路的坐标写成 QPainterPath 的顶点调用）
和**简化**上，属于每个比例尺只付一次的代价，不是每帧成本。

> 上表是渲染集管线的历史数据。启用 provider 后，源文件的「载入」只剩读文件头，
> 首屏时间变成「bbox 读取 + 分块绘制」；Shapefile 首屏仍要顺序扫描一次，GPKG 有索引更快。

### 为什么没有上 OpenGL

`tools/perf_backend.py` 在真 GL 上下文（4.6）+ 离屏 FBO 里画**同一份渲染集**，逐图层对比
（每一项都统计落笔像素，防止「路径被挪到画布外、只量到裁剪时间」的假结果）：

| 图层（省域视图 951 m/px） | 几何 | CPU 光栅 | OpenGL |
| --- | --- | --- | --- |
| 用地 landuse | 28 条面批 | **106 ms** | 921 ms（慢 8.7 倍） |
| 建筑 buildings | 24 万个点（`drawPoints`） | **16 ms** | 1963 ms（慢 124 倍） |
| 水系 water | 20 条面批 | **45 ms** | 323 ms（慢 7.1 倍） |
| 道路 roads | 1958 条线批 | 79 ms | **38 ms（快 2 倍）** |

结论：GL 只在**线描边**上占便宜，遇到「大量小面 / 大量点」反而慢一个数量级 ——
QPainter 在 GL 上要把路径三角化（stencil-and-cover），而 CPU 光栅对大量小图元有更直接的路径。
整帧实测 4 层一起画：CPU 350 ms vs GL 5975 ms，所以渲染后端保持 CPU 光栅，
性能花在「1px 笔宽 + 包围盒向量化」上（上面那两行表格就是收益）。
脚本留着：换机器、换驱动、或者以后要画「粗线条风格」时，先跑它再决定要不要搬。

`tools/verify_render.py` 就是这套验证脚本：真实数据 + 离屏渲染，跑
「省域 → 逐级放大 → 平移 → 缩回」，最后清空渲染集重建同一视口逐像素比对 ——
如果渲染集的范围/要素有偷工减料，两次画面就会不一样，差异区域正好就是
屏幕上那些「没渲染出来的块」。截图见 `docs/perf/verify-*.png`。

> 已知边界：`geopandas.read_file` 在后台线程里会较长时间持有 GIL，
> 载入超大 Shapefile 时主线程仍会被拖住。已通过「串行载入 + 载入期间暂停构建 +
> 读 `.cpg` 编码一次读对（不再三遍择优）」把影响降到最低。


### 栅格渲染管线（第二条管线，与矢量完全隔离）

栅格和矢量是**两条互不相干的管线**。矢量那边的一切（渲染集、简化、按批合并、
几何缓存）对栅格完全不适用，所以栅格自己一套，代码在 `native/rasterview.py`，
矢量管线一行没改。

隔离靠的是一个很薄的缝：`MapView.set_layers()` 把图层分成 `_vec_layers` 和
`_raster_layers`，**栅格不建 `_LayerCache`**。矢量渲染的每个循环都是
`if self._cache.get(id) is None: continue` 开头，于是栅格天然被所有矢量逻辑跳过 ——
不需要在每个循环里加 `if is_raster: continue`。

| 本项目 | QGIS 对应 | 说明 |
| --- | --- | --- |
| `RasterViewPort` | `QgsRasterViewPort` | 视口快照：范围、像素尺寸、缩放、dpr |
| `_RasterItem` / `_RasterJob` | `LayerRenderJob`（栅格版） | 每个栅格自己一张全视口透明 QImage |
| `_RasterWorker` | `QgsMapRendererParallelJob` | 独立渲染线程，只保留最新请求 |
| `render_layer_image()` | `QgsRasterLayerRenderer::render()` | 求像素矩形 → 按目标尺寸取块 → 画进视口图 |
| `read_window()` | `QgsRasterIterator::readBlock()` | **按屏幕像素尺寸抽取**，不整幅读入内存 |
| `RasterSourceCache` | `QgsRasterBlockCache` | **源 overview 固定像素块**，LRU 按字节限额，键不含视口 |
| `RasterTileCache` | `QgsMapRendererCache`（屏幕 tile 版） | 世界坐标固定网格 tile，同一比例尺平移复用 |
| `resampling` | `QgsRasterResampleFilter` | nearest / bilinear / cubic / average |
| `percentile_stretch()` | `QgsContrastEnhancement` | 累计裁剪拉伸（默认 2%–98%） |

要点：

- **只读屏幕需要的像元**：`read_window()` 用 rasterio 的窗口读 + `out_shape` 降采样；
  源窗口超过 400 万像元时按**目标图像块**（256×256，外扩 2 px）切分，
  每个块的源窗口边界落在全局输出网格的整数边界上再分别解码。按源块切会让
  每块自己的重采样比例和全局不一致，nearest 在接缝处整段错位；按目标块切
  可以做到和整窗读取逐像素一致（`tools/test_raster_block_read.py`）。
  1 万×1 万的 GeoTIFF 在 700 px 视口里只保留屏幕大小的输出；载入时只读
  文件头（`read_info()`，不碰像素）。
- **GDAL 块缓存封顶**：`GDAL_CACHEMAX=128 MB`，可用 `GIS_AGENT_GDAL_CACHE_MB`
  调整。不设时 GDAL 会按物理内存比例给缓存，448 MB / 613M 像元的 TIFF 一次
  整窗读取峰值可到 1.4~1.9 GB；封顶后同样窗口的 WorkingSet 约 80 MB。代价是
  无 overview 时首帧会慢很多，所以大栅格仍建议生成金字塔（有 `.ovr` 时读取
  走缩减层，0.3 s 级，且会跳过目标块分块）。
- **源 block cache（对应 `QgsRasterBlockCache`）**：先按目标抽取倍率选
  overview 层，再按该层的固定 **256×256 源像素块**读取，块图像是拉伸后的
  RGBA。键是 `(图层, rev, 样式, overview factor, bx, by, 块尺寸)`，**不含
  scale/tx/ty**，所以平移、放大、缩小到同一 overview 层都能复用；上限
  **64 MB / 512 块**，按 QImage 实际字节数淘汰。
  448 MB / 20673×29673 的 TIFF 在 900×640 视口实测（直接调用
  `render_layer_image`）：全图首帧 136ms、同视口重绘 10ms、连续放大
  28/50/51/46ms、缩小 15/16/12/10ms；对比旧的整窗路径每次缩放都要
  0.3s~几十秒。
- **屏幕 tile cache**：同一比例尺平移时按世界坐标固定网格复用逻辑 256px
  tile。首帧用整窗/分块读取，画完把**完整落在视口内**的 tile 裁进 LRU；
  键是 `(图层, rev, 样式, scale, dpr, ix, iy)`，不含 tx/ty；上限
  **64 MB / 512 块**。源影像不足 200 万像元时默认不切 tile
  （整窗一次读完更快、也没有边界误差）；大图默认开启。
  `GIS_AGENT_RASTER_TILES=0/1`、`GIS_AGENT_RASTER_BLOCKS=0/1` 可强制关闭/开启。
- **overview 管理**：载入时仍会问一次是否生成 `.ovr`（不改原 TIFF）；
  如果用户暂不生成，之后**可见大栅格首次渲染/缩放**时 `MapView` 发
  `overviewNeeded`，主窗口用后台 `PyramidWorker` 补 `.ovr` 并在状态栏显示
  进度，不阻塞地图交互。生成完成后刷新该栅格所有图层的 `info.overviews`、
  清空 stats/源块缓存，下一次缩放自动选中缩减层。
- **统计抽样**：拉伸统计用 `sample_stats()`：有 overview 时读 512×512
  缩减层，无 overview 时均匀取 8×8 个 256×256 源块，不再为了 percentile
  扫全图（这是旧逻辑第一次缩放卡几十秒的另一个原因）。
- **不按视口裁剪图片**：和矢量一样，每个栅格渲染成**整视口大小**的透明图，
  `_compose()` 只需多一句 `drawImage(0, 0, img)`，不用管偏移。
- **过期图不扔，按自己的视口挪过去**（这一条决定了拖拽的手感）：视图一变，
  手上的图层图就过期了，但新图还在后台线程里渲。直接按 `(0, 0)` 贴等于把整个世界
  拉回原处 —— 用户看到的正是「松手后先跳回拖拽前的样子，过一会儿才归位」。
  所以每张图都记着自己是按哪个视口渲的（`_layer_views` / `RasterPipeline.view_of()`），
  合成时套一次

      translate(tx, ty) · scale(s / s0) · translate(-tx0, -ty0)

  世界坐标里的点 w 在旧视口下是 `p0 = w·s0 + tx0`，代入得 `w·s + tx`，正好是它在新视口下
  的位置 —— 纯平移是精确的整数位移，缩放是以视口为基准的精确等比变换。代价只有
  「旧图分辨率不够 / 边缘缺一条」，位置始终正确。这套规则**矢量和栅格共用**
  （`MapView._blit_view_image`），因为矢量的图层图也是整视口大小的，同样会过期。
- **栅格回调不能抢矢量中间帧的合成线程**：栅格是异步的，它完成时矢量 job 可能还在跑。
  用 `_vec_busy` 闸住：矢量空闲才允许栅格驱动一次整帧合成；否则只把栅格图存进
  `_raster_imgs`，等矢量中间帧/final 帧合成时自然带上。首次出图（`_frame is None`）
  例外，让栅格先显示，避免空白。
- **合成层是两条管线唯一的共用写画布路径，必须逐层兜底**：`_compose()` 里栅格先画，
  任何一层抛异常都会让后面的矢量整片消失；而且异常发生在 `p.save()` 之后会把画笔
  留在活跃状态，后续合成全部报 "paint device can only be painted by one painter"。
  所以每层单独 `try/except` + `finally: p.end()`，一层坏了只丢那一层。
- **所有进 `_blit_view_image()` 的坐标必须先转 Python `float`**：`fit_bounds()` 直接吃
  `gdf.total_bounds` 的 `numpy.float64` 时，`scale/tx/ty` 也会是 numpy 标量，
  `abs(scale/s0 - 1) > 1e-9` 得到 `numpy.bool_`，`QPainter.setRenderHint()` 不接受，
  会抛 TypeError。`fit_bounds` / `zoom_at` / `RasterViewPort` 三处都已归一。
- **缓存键与矢量同构**：`(scale, tx, ty, w, h, dpr, rev)`。平移/缩放没变化就直接复用，
  `request()` 返回 `False` 表示整帧都有缓存，一帧都不用重算。
- **投影共用一套函数**（`native/proj.py`）：两条管线各自实现 Web Mercator 早晚会算出
  半像素的偏差，栅格和矢量叠在一起就是「地块压不住影像」。
- **N 波段 → RGBA**：3/4 波段按 RGB(A) 合成，单/双波段走灰度 + 百分位拉伸；
  `nodata` 写进 alpha=0，不要用黑色填充（不然影像边界会出现一圈黑边）。
- **`QImage` 必须 `.copy()`**：numpy 的缓冲区 Qt 不持有所有权，直接 `fromData`
  会在一帧后被回收成花屏。

### 通用栅格工具（8 个，与矢量算子同一套契约）

栅格不只能看，也能像矢量一样被自然语言/工具库调用。实现集中在 `app/raster_ops.py`：
裁剪/重投影/重采样/计算/镶嵌返回新的 GeoTIFF 图层，`raster_info` 只体检、
`zonal_stats` 返回带统计字段的面图层；原始文件只读不改。rasterio 只在真正执行时导入，
纯矢量流程的启动不加载 GDAL。

| 工具 | 作用 | 关键参数 |
| --- | --- | --- |
| `raster_info` | 栅格体检：尺寸、波段、dtype、CRS、分辨率、nodata、各波段抽样统计 | `layer` |
| `raster_clip` | 按经纬度 bbox 或面图层裁剪 | `layer`、`mask` / `bbox`、`all_touched` |
| `raster_reproject` | 重投影到目标 EPSG | `layer`、`epsg`、`resampling`、`resolution` |
| `raster_resample` | 按比例或目标分辨率重采样（0.5 = 宽高减半） | `layer`、`scale` / `resolution`、`resampling` |
| `raster_calc` | 栅格计算器：`b1…bN` + 四则/`where`/`clip`/`sqrt` 等，输出单波段 float32 | `layer`、`expression` |
| `zonal_stats` | 分区统计：把栅格值按面汇总，给面图层新增字段 | `layer`（面）、`raster`、`band`、`stats` |
| `raster_merge` | 多栅格镶嵌（要求同 CRS / 波段数 / dtype） | `layers`、`resampling`、`nodata` |
| `raster_to_vector` | 按像元值转面（polygonize），`scale` 控制要素数量 | `layer`、`band`、`scale` |

实现要点：

- **按窗口/按块处理**：裁剪用 `rasterio.mask` / `Window`，重投影按输出块 `reproject`，
  栅格计算按 1024×1024 块读写，分区统计对每个面用 `geometry_window` 只读覆盖的像元；
  大影像不会整幅读进内存。
- **NDVI 就是栅格计算**：`(b4-b3)/(b4+b3)` 用 `raster_calc` 跑，不必为每个指数写死一个算子。
- **栅格/矢量在规划层也分流**：`validate_plan()` 会在执行前拒绝「对栅格做缓冲区」这类
  请求，并给出可用的栅格工具；`zonal_stats` 是唯一同时吃「面 + 栅格」的工具。
- **$prev 串联**：和矢量一样，上一步的栅格结果可以用 `$prev` 传给下一步，
  例如「裁剪影像 → 对结果重采样」。
已知边界：栅格仍没有属性表、不能做矢量叠加（误操作会在校验期得到一句中文错误），
也没有拉伸/伪彩色面板（默认参数写死在 `RasterLayer.style` 里）。


## 支持的格式

读：`.zip`（可含多个 shp / GeoTIFF，弹窗勾选要载入哪些）、`.shp`、`.geojson/.json`、`.gpkg`、`.kml`、`.gml`、`.csv`（经纬度列或 WKT 列）
栅格读：`.tif/.tiff`、`.img`、`.vrt`、`.jp2`（依赖 `rasterio`，它自带 GDAL）
FileGDB：`.gdb` 文件夹（Esri File Geodatabase，依赖纯 Python 的 `pyopenfilegdb`）
写：GeoJSON、GeoPackage、Shapefile（zip）、CSV（含 WKT）；栅格「导出」是复制原文件，不做重编码

### Esri FileGDB（.gdb）

`.gdb` 是**文件夹数据库**，一个库里可以有多个要素类。点顶栏「＋ GDB」选文件夹，
或直接把 `.gdb` 文件夹拖进窗口：

- 列出库里所有要素类，逐个导入为图层，名字是 `库名/要素类名`（如 `2024国土/村行政区划`）；
- 属性、几何、坐标系（WGS84 / CGCS2000 3 度带等）都保留，后续和普通矢量图层一样做算子；
- 也支持压缩包里放 `.gdb` 文件夹；
- 读取走纯 Python 的 [`pyopenfilegdb`](https://github.com/lizhiziwang/pyopengdb)，
  不依赖 GDAL / fiona：

  ```bash
  pip install "pyopenfilegdb @ git+https://github.com/lizhiziwang/pyopengdb.git"
  ```

  没装时打开 GDB 会给出这条安装提示，不影响其他格式。它自带的
  `_gdbaccel` C 扩展会加速 GDB 的二进制解码；本项目再用
  `Geometry.xy_parts + shapely.from_ragged_array` 批量转 GeoDataFrame，
  350 MB / 2.4 万面的库实测从逐要素转换的约 88 秒降到约 8 秒。

### 大图层：内存预算 + 磁盘换出

`Store` 支持按内存预算把不活跃的大图层换出到 `data/cache/`：

- 默认预算 `2048 MB`，可用 `GIS_AGENT_MEMORY_MB` 调整；设为 `0` 关闭换出；
- 小于 `GIS_AGENT_CACHE_MIN_FEATURES`（默认 2 万要素）的图层不换出；
- 缓存目录可用 `GIS_AGENT_CACHE_DIR` 指定；
- 有 `pyarrow` 时用 GeoParquet，否则用 GeoPackage；
- 换出后 `Layer.meta()` 仍走缓存（count/bounds/fields 不重新读盘），下次访问 `layer.gdf` 时懒加载；
- 删除图层 / 清空项目会清理对应缓存文件。

## Agent 运行时：多任务 · 会话 · 记忆

桌面端不再是一个 Worker + 一个 `_busy` + 内存 history，而是**可排队、可取消、可恢复、
会话可持久化、记忆分层**的运行时。设计细节见
[docs/AGENT-RUNTIME-DESIGN.md](docs/AGENT-RUNTIME-DESIGN.md)。

**多任务**

- 聊天 / 导出 / 导入 / 生成算子都进同一个优先级队列（聊天 100 > 生成算子 90 >
  导出 70 > 导入 60），单写通道串行执行——GIS 算子会新建图层，并行写要上 MVCC，第一版不做。
- **地图顶部居中**显示任务通知：执行中 / 排队中 / 已完成 / 失败一目了然，
  可以**取消**排队或执行中的任务、**重试**失败的任务、**看日志**回放这次运行；
  通知不占用右栏对话空间，完成后自动消失，失败会保留更久。
- 分析运行中导出不再被拒绝，而是排到队列后面；不再覆盖 `_worker`，没有 QThread 崩溃风险。
- 取消是**协作式**的：长 GEOS 调用杀不掉，语义是「当前步骤跑完后停止」，界面显示「正在取消…」。
- 关窗时若有任务在跑会先问一句：等它跑完，还是取消并关闭。

**会话持久化**

- 消息、运行、步骤、事件、图层元信息、记忆全部落在 `data/agent.db`（SQLite WAL + 外键）。
- 每次运行的完整事件流可回放（「日志」按钮），失败能看出失败在哪一步。
- 上次退出时没跑完的任务，重启后标记为 `interrupted` 并提示——**不会自动重跑**
  （免得刚开应用就偷偷跑 50 万要素的 overlay）。
- 图层元信息（字段、CRS、要素数、范围）入库，删图层是逻辑删除，历史可追溯。

**记忆**

- **四类**：偏好（默认单位 / CRS / 导出格式）、项目事实（图层字段与 CRS）、
  工作流（成功的多步计划）、纠正（「不是道路，是管线」「按类型」→ 真实字段 `用地类型`）。
- 自动提取规则可解释，全部本地存储，不上传、不存原始属性表、不存密钥。
- 检索用 FTS5 trigram（中文友好）+ 结构化 key，冲突按「偏好 > 纠正 > 项目事实 > 工作流」消解，
  注入 prompt 时截断到预算内。
- 顶栏「◈ 记忆」打开管理面板：分组查看、编辑、置顶、删除、清空，以及 JSON 导入导出。
- 会话消息攒够会压成一句摘要（原文保留，随时可翻）。

```bash
# 跑全部回归测试（21 个，约 2 分钟）
.venv\Scripts\python.exe tools\run_regression.py
```

## 扩展一个新算子

这是开发者视角（写代码加算子），和界面上「＋ 新建工具」（让大模型写）不是一回事。

1. 在 `app/engine.py` 写 `def _my_op(store, layer, ...) -> Result`，返回 `Result(ok, message, new_layer, warnings, data)`；
2. 注册到 `OPERATIONS`（矢量在 `engine.py`，栅格在 `raster_ops.py`）；
3. 在 `app/tool_registry.py` 加 `ToolSpec`（参数 schema / 中文名 / 分组），
   大模型提示词、工具库按钮、参数校验会自动读到；
4. 若是栅格算子，还要在 `native/app.py` 的 `RASTER_TOOL_GROUPS` 里归到「概览 / 处理 / 分析 / 转换」之一；
5. 若要支持固定说法，在 `_parse_clause` 里加一条正则分支。

## 已知边界

- 单机单会话；源文件图层默认只读文件头、按 bbox 渲染，不把整层读进内存；
  算子/导出/拾取等需要全量数据时才懒加载。内存图层超过 `GIS_AGENT_MEMORY_MB` 的
  不活跃大图层会换出到 `data/cache/`，关掉窗口后需重新载入（已导出的文件不受影响）。
- **要素不抽样**：视口内的要素会全量进渲染集，没有「超过 N 个就抽稀」的开关 ——
  抽样是有意去掉的，它会在屏幕上留下成块的空洞。性能靠「1px 笔宽、按批合并路径、
  亚像素要素降为点」而不是靠少画要素。
- provider 支持的源文件图层导入只读文件头（毫秒级）；首屏要按屏幕 bbox 从源文件取一次窗口。
  Shapefile 没有空间索引时这一步仍会顺序扫描 `.shp`（只是不把范围外要素读进内存），
  77 万要素的道路首屏通常要几秒；GPKG 有空间索引时会快很多。
  CSV、FileGDB、ZIP 解压临时文件仍回退整份读取。
- 默认底图是经纬网；需要在线底图时用工具库「底图 → 在线地图」添加 XYZ/WMTS/WMS，
  天地图选 WMTS、Token 参数名填 `tk`；不添加就不联网。在线瓦片依赖网络与目标服务可用性，服务端限流/证书问题会在图层上
  显示为空，不会影响本地矢量数据。需要鉴权的服务在弹窗里填 Token/自定义请求头；开启
  会话持久化时 Token 随会话状态保存在本地 SQLite（不写入日志/聊天消息），恢复会话时
  会重新用于请求。
- 规则引擎覆盖常见中文表达，长句、口语化、多目标推理建议接大模型。
